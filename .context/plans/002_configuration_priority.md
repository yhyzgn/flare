# 计划 002：配置优先级修正

- 状态：已完成
- 负责人：未分配
- 当前任务：`.context/tasks/002_configuration_priority.md`

## 目标

修正 `@EnableFlare`、`@Flare`、方法级/参数级动态代理注解之间的配置优先级，使外层配置只作为兜底，越靠近实际代理方法的配置越优先。

## 非目标

- 不做大范围重构。
- 不改发布版本、发布流水线或 Maven Central 配置。
- 不提交、不推送。
- 不调整与本优先级问题无关的上传、下载、转换器或调用适配语义。

## 约束

- 修改公共注解默认值前必须说明兼容性影响，并用测试覆盖继承/覆盖行为。
- Spring 注册器和核心请求构建链路都要有特征化测试。
- 拦截器生命周期属于高风险区域，除非测试证明与优先级问题直接相关，否则不扩大改动。

## 依赖关系

```text
现状定位 → 特征化测试 → 最小代码修正 → 定向测试 → 构建验证 → 上下文沉淀
```

## 阶段

1. 定位 `@EnableFlare` 与 `@Flare` 注册合并逻辑。
2. 定位核心 `RequestFactory` 中方法/参数 Header 与全局 Header 的合并逻辑。
3. 增加覆盖全局兜底、局部覆盖、方法/参数覆盖的测试。
4. 执行定向测试与最小构建验证。

## 检查点

- 修改前回滚点：恢复 `RequestFactory`、`AbstractFlareAutoRegister`、`Flare` 注解和新增测试文件。
- 验证失败时先回退最新小步改动，不继续扩大重构范围。

## 计划级风险

- `@Flare` 注解默认值是公共 API，改为三态继承语义可能影响依赖默认开启日志或默认超时的用户。
- Header 与 interceptor 都可能通过 OkHttp 顺序体现优先级，不能把执行顺序和覆盖语义混为一谈。

## 完成标准

- `@EnableFlare` 全局 Header / 动态 Header / timeout / logEnabled 只作兜底。
- `@Flare` 显式配置能覆盖全局配置；未配置时继承全局。
- 方法级和参数级 Header 能覆盖 Builder / Spring 全局 Header。
- 定向测试和必要构建检查通过，验证证据记录到当前任务。
